# 社区康复中心 · 器械预约与训练风险提示系统

## 原始需求

> 设计社区康复中心器械预约与训练风险提示页面，可使用 React、TypeScript 和 Zustand。患者建档后，页面记录诊断、术后阶段、活动范围、禁忌动作、疼痛评分、家属陪同、医保项目和治疗师。预约训练时，页面根据器械类型、治疗师排班、患者风险、训练时长和上一轮反馈生成可预约时间。到场后，治疗师核验患者状态、血压、疼痛、伤口和是否适合当天训练；训练中记录关节角度、阻力、次数、心率、疼痛变化和异常中止。若患者迟到、家属要求加量、器械故障、训练后疼痛加重、医保次数不足或治疗师临时请假，页面要把前台、治疗师、患者、家属和设备维护放到同一康复计划中处理。训练结束后，疗效反馈、下次预约、风险提示、器械消毒和维护状态进入档案，治疗师可以持续调整方案。页面还要区分术后康复、慢病功能训练、儿童康复和老年平衡训练，不同人群的风险提示、家属参与和治疗师评估项不同。若患者中途转诊、暂停训练或医生调整方案，页面要保留原计划与新计划的衔接。对于高风险患者，页面还要要求治疗师在训练前确认医生医嘱、家属知情和紧急联系人；训练后若出现延迟疼痛，患者端可以继续反馈并触发复诊建议。

### 迭代需求（训练中疼痛升级处理）

> 增加训练中疼痛升级处理。患者在膝关节训练中疼痛突然升高时，页面提示治疗师暂停、记录动作角度、冰敷或通知医生。处理结果会影响下次训练强度、家属提醒和风险标签。疼痛升级事件会进入治疗师交班，下一位治疗师能看到中止原因和医生建议。交班记录会带上疼痛评分变化和患者主观描述，下一次训练不会只看预约状态。

## 系统简介

面向社区康复中心的一体化工作台，覆盖 **建档 → 预约 → 到场核验 → 训练执行 → 反馈归档 → 异常协同 → 计划衔接** 全流程：

- **五角色协同**：前台、治疗师、患者、家属、设备维护，所有异常（迟到/加量请求/器械故障/疼痛加重/医保不足/请假/延迟疼痛等）都进入同一个「协同事件」看板，在同一康复计划内按角色留痕处理。
- **智能预约**：可预约时段由后端依据 器械状态与适用人群、治疗师排班与请假、既有预约冲突、患者风险等级（高风险仅开放低负荷时段）、训练时长、上一轮反馈（疼痛/延迟疼痛自动拉长间隔）与**最近一次训练中疼痛升级（按建议间隔排期，未交班知悉时给出醒目警告）**综合生成；医保次数不足时阻断并支持自费确认，自动生成协同事件。
- **人群差异化**：术后康复 / 慢病功能训练 / 儿童康复 / 老年平衡训练 四类人群，各自的默认时长、核验评估项、训练记录项、风险提示与家属参与要求均不同。
- **风险闭环**：建档自动评估风险等级（低/中/高）；高风险患者训练前强制「医嘱确认 + 家属知情 + 紧急联系人」三项确认；训练中心率超阈值、疼痛加重实时告警；训练后疼痛≥6 分自动生成协同事件；患者端可持续反馈延迟疼痛并触发复诊建议。
- **训练中疼痛升级处理（膝关节训练场景）**：训练页输入疼痛峰值即提示治疗师按「① 暂停 → ② 记录诱发动作角度（膝关节屈曲角度）→ ③ 冰敷 15-20 分钟 → ④ 通知医生」处置，并填写疼痛升级处理单（疼痛评分变化 + 患者主观描述原话）。系统按分级（升高≥3 分/峰值≥6 为升级、≥8 为剧烈疼痛）自动给出**下次训练强度与间隔建议**、生成**家属提醒**文案、给患者打上**疼痛风险标签**（标签随交班知悉可评估解除）。升级事件自动进入治疗师**交班看板**，支持回填医生建议；下一位治疗师在下次训练**到场核验时被强制阅读交班卡（中止原因/疼痛变化/主诉/医生建议）并勾选知悉**后才能开始训练——不会只看预约状态；正常完成训练时交班自动闭环。
- **计划衔接**：转诊、暂停、医生调整方案均生成新计划版本并保留与旧计划的衔接说明，历史训练记录完整可查。

## 技术栈与架构

```
web/     React 18 + TypeScript + Zustand + Vite（五角色页面）
server/  Node.js + Express + better-sqlite3（REST API + 规则引擎 + 种子数据）
Docker   多阶段构建：前端构建 → 后端依赖 → 非 root 运行时（HEALTHCHECK）
```

- 数据库：SQLite（内嵌于应用容器，挂载卷 `rehab-data` 持久化），首次启动自动建表并注入演示数据。
- 规则引擎（`server/src/domain/`）：风险分级、人群配置、时段生成、核验/训练评估，前后端共用同一套阈值。

## 一键启动（Docker）

```bash
cp .env.example .env        # 可选：修改 CC_PUBLISH_PORT
docker compose up -d --build
docker compose ps           # 等待 app 容器 healthy
```

访问：`http://localhost:<CC_PUBLISH_PORT>`（验证环境端口由 `CC_PUBLISH_PORT` 注入，可用 `docker compose port app 8080` 查看实际映射）。

停止：

```bash
docker compose down         # 释放资源；数据保留在 rehab-data 卷中
docker compose down -v      # 如需清空演示数据重新初始化
```

## 推荐演示流程

1. **前台**（frontdesk）：今日日程给「张伟 10:00」登记到场（姓名旁可见「疼痛高风险」标签与「疼痛交班待知悉」标记）；到「预约训练」体验时段生成（张伟的可预约时段会出现"疼痛升级尚未交班知悉"警告；刘芳医保仅剩 3 次有提示）。
2. **治疗师**（therapist1）：「今日执行」打开张伟核验 → 系统因昨日疼痛升级（4→8 分）**强制弹出交班卡**（疼痛变化、患者原话"膝盖里面突然刺痛，不敢再弯"、诱发角度屈膝约92°、医生建议），勾选知悉后才能开始训练 → 在训练记录区输入疼痛峰值（如 8）→ 点「填写疼痛升级处理单」：记录疼痛变化/患者主诉/诱发角度、勾选暂停·冰敷·通知医生·家属提醒，提交后可见分级处置清单、下次强度建议与新增风险标签。
3. **疼痛交班**：therapist1 顶部「疼痛交班」页查看待知悉记录、补录医生建议；也可点「我是下一位治疗师，已知悉」（可选解除疼痛标签）。本次训练若正常完成，交班会在完成时自动闭环；若再次升级则保持待知悉。
4. **高风险确认**：therapist1 核验「陈桂香 14:30」——缺少三项确认会被拒绝；先用 family3 在线「确认知情」，再完成三项确认开始训练。
5. **异常协同**：therapist1「请假与排班」请明天假 → frontdesk「协同事件」中看到受影响预约，执行改派/改期并标记解决；maint 将「下肢功率车」登记故障 → 事件自动关联受影响预约。
6. **患者端**：patient1 顶部可见疼痛升级复诊横幅，「我的预约」展示疼痛升级提醒与下次低强度安排；patient2 在「训练反馈」对历史训练提交延迟疼痛 7 分 → 触发复诊建议横幅，therapist2 在协同事件中跟进。
7. **家属端**：family1「患者概况」顶部可见张伟疼痛升级家属提醒（评分变化/处置/医生建议/下次强度），并可在「请求与协同」提交「加量请求」→ therapist1 在协同事件中评估回复。
8. **计划衔接**：therapist1 打开「我的患者 → 张伟 → 调整方案」生成 v2（医生调整方案），查看版本链衔接说明与疼痛交班历史；或执行暂停/转诊。

## 验证方式

以 **宿主 docker compose 启动健康 + 关键业务流走通** 为验证标准：

```bash
docker compose up -d --build
PORT=$(docker compose port app 8080 | cut -d: -f2)
curl http://host.docker.internal:$PORT/api/health
# → {"ok":true,"service":"rehab-center",...}
# 浏览器打开 http://localhost:$PORT ，用上表账号登录，按「推荐演示流程」走通各角色业务流
docker compose down
```

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `CC_PUBLISH_PORT` | 8080 | 宿主机发布端口（compose 映射到容器 8080） |
| `PORT` | 8080 | 应用容器内监听端口 |
| `DATA_DIR` | /app/data | SQLite 数据目录（容器内，挂载 rehab-data 卷） |
| `TZ` | Asia/Shanghai | 时区（影响"今日"日程与时段生成） |

## 说明与边界

- 本项目为演示工程：口令使用静态盐 SHA-256 散列、会话令牌存于 SQLite，生产环境应替换为 bcrypt/argon2 与标准会话/OIDC 方案。
- 风险阈值（心率系数、血压/疼痛/血氧界值）为演示规则，集中在 `server/src/domain/`，可按临床规范调整。
